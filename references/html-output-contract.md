# HTML 交付规范

普通正式分析默认交付可离线打开的本地 `report.html`，不是网站或应用。`repeated_operational_tables` 是例外：主要交付物为可筛选、可下钻 Excel，HTML 只是简要阅读版。普通路线以 `deep_analysis.json` 为准；经营表路线以标准事实层和经营分析产物为准。

## 读者阅读顺序

1. 精简标题和范围；
2. 能支持决策的结论摘要，以及证据/发现/动作概览；
3. 抽样规则、确认的分析单位、指标定义、证据覆盖和数据能证明什么；
4. 完整发现，每条包含事实、证据、解释、反例、边界和关联动作；
5. 成对比较和路线专属模块；
6. 全部建议与可控实验；
7. 缺失证据和未回答问题；
8. 真正影响解释时才展示安静的读者提示。

不要用流程叙述开场。图表只用于真实关系，例如已审核证据数量、发现分类、成熟度、流程或动作优先级。不能把原始文件数画成虚假的共识图。

## 可携带性

- 保存为 UTF-8；
- CSS 和必要数据内嵌；
- 不使用网络字体和外部 CDN；
- 可选本地附件只用相对链接；
- 注入 HTML 前转义所有来源文本；
- 读者 HTML 不显示本地绝对路径、哈希、路线 ID、深度、合同版本、原始证据 ID 和方法文件清单；
- 渲染或分享前扫描可能的密钥和个人信息，日志中不得保存命中值。

## 视觉基线

- 安静的浅色背景；
- 明确但克制的强调色；
- 可读的中文系统字体；
- 紧凑报告页眉，不做落地页式巨型首屏；
- 统一使用 4/8/12/16/24/32/48 间距，不出现占满视口的空白面板；
- 先摘要，再进入完整单栏分析，宽屏可提供分组阅读导航；
- 合同 2.3 存在优先级时，建议按“现在做 / 接着做 / 以后做”分组；
- 宽表响应式横向滚动；
- 窄屏平台筛选或标签可以换行或横向滚动，不能裁字；
- 窄屏阅读导航压缩为页面内部横向滚动条，不能占满首屏；链接触控高度不低于 44 像素；
- 事实、线索、警告和动作有明显区别；
- 打印结果可用。

使用 `assets/report-template/report.css` 和 `scripts/render_report.py`，然后运行 `scripts/validate_outputs.py`。
图库使用相对路径时，可向渲染命令重复传入 `--asset-root`，把其中已存在的图片复制到报告目录并沿用现有输出清单记录；缺失资源只在命令结果中报告，不另设发布门。

经营表 HTML 不倾倒全部事实行，只展示对账后的核心总量、平台对比、阶段变化、变化/覆盖候选、边界和优先核查。完整事实与下钻保留在工作簿。至少检查约 390 像素和 1280 像素宽度，并记录页面是否存在整体横向溢出。

图库可以使用 `fit=contain` 或 `fit=cover`，以及 `50% 20%` 等安全 `position`。只有裁切提升可读性且不隐藏证据时才裁切。

渲染器不能删减发现、比较、路线章节、建议或实验。机器审计字段只有在完整保留于 `deep_analysis.json`、无损 Markdown 和 `run_manifest.json` 时，才可不展示在读者 HTML。

抽样和证据覆盖是读者需要知道的边界，不是流程日志，要用大白话表达。内部置信度、关键词命中、哈希、文件路径和脚本名保持隐藏。

完成状态文案只陈述声明范围。默认写“已完成本轮分析，实际覆盖见下文”，不得自动声称已全量审阅全部历史、全部图片或所有资料族；确需更具体时使用经过核对的 `presentation.completion_note`。

## 阅读导航

- 使用分析产物提供的 `presentation.toc_groups`；
- 标签用普通中文描述读者问题或结果；
- 把相关章节组织成少量阅读路径，不列出内部字段层级；
- 目录不展示方法追踪、证据索引、限制清单和未回答问题清单；
- 只有对应章节存在时才使用 `coverage` 和 `experiments` 锚点，并命名为“这次样本能说明什么”“下一轮怎么验证”等读者问题。
