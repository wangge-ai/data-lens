# 无预设角度发现

当用户提供资料但不指定分析角度时，Data Lens 不能把请求退回成泛泛的“请明确问题”，也不能一次罗列大量没有证据计划的问题。角度发现是一道受约束的候选生成与筛选过程，不是独立事实来源。

## 先锁定范围

- 只读取用户明确指定的资料类型、目录和时间范围；配套图片、视频或同文异格式不能因为同处一个文件夹就自动进入必需证据。
- 先去重并定义分析单位。未确认同一作者时使用通用质性语料路线；作者或账号元数据一致后，才可升级为同一作者内容路线。
- 小于或等于 20 个可读文本单元时优先全量；更大语料使用主题、时间和形态平衡的分层样本，禁止顺序取前几项。
- PDF 合集必须先拆开“物理文件、页面、内部项目/章节”三层。文件数不是分析单位数；目录、页形变化和 OCR 标题只能提出边界候选，经过页码/图像复核后才能登记为内部单元。边界未确认时不得据“两份 PDF”生成跨案例频次或比例。
- 超长图像页先按低 DPI、小页数上限做结构试样；页高变化页只能占少量异常名额，其余名额必须覆盖前、中、后段。结构试样成功不等于内容代表性成立。

## 候选角度从哪里来

先建立“单元 × 可观察维度”地图，再从以下信号提出候选：

1. 跨单元稳定重复的结构或证据习惯；
2. 主题、时间、长度、任务或载体之间的明显差异；
3. 与主模式相反的异常样本、冲突或边界案例；
4. 同一对象随时间出现的变化；
5. 用户下一步能据此选择、改进或验证的决策问题；
6. 预期存在但实际缺失的证据通道，但只能写成缺口，不能写成事实。

每个候选必须记录：`angle_id`、问题、为什么值得看、分析单位、所需证据、覆盖计划、可能反例、失败条件和当前状态。

## 角度筛选门

最多形成 8 个候选，最多采用 4 个。逐项检查：

- 与用户目标是否相关；
- 能否仅凭声明范围内的资料回答；
- 是否有覆盖多个单元且包含反例的证据计划；
- 是否与其他候选实质不同；
- 是否能产生可行动或可验证的判断；
- 是否存在把频次当效果、把风格当动机或把共现当因果的越界风险。

没有表现数据时，不采用“什么内容更受欢迎、什么写法效果最好”这类角度；可以分析内容机制并提出后续实验。没有作者范围依据时，不采用人格、动机或完整账号画像角度。

## 采用链

```text
语料地图
→ 候选角度
→ 角度筛选门
→ 分角度证据卡
→ 合同校验
→ 证据校验
→ 角度采用账本
→ 只读取已验证证据卡的有界跨篇综合
```

候选语义可以由宿主智能体提出，但不得由它自行宣布采用。候选批次遵守 `contracts/angle-candidates.schema.json`，然后运行：

```text
python scripts/data_lens.py compile-angles --candidates angle-candidates.json --evidence-cards evidence-cards.json --output angle-adoption-ledger.json
python scripts/data_lens.py validate-adoption angle-adoption-ledger.json
python scripts/data_lens.py synthesis-context --ledger angle-adoption-ledger.json --output synthesis-context.json --max-cards 24 --max-chars 24000
```

`compile-angles` 先适配字段，再逐候选完成合同和证据校验；请求失败、合同缺字段、未知证据或未验证证据都会阻止采用。不得按输入顺序静默截断超过 8 个候选或超过 4 个拟采用角度，输入超限时整批失败并要求重新筛选。

`synthesis-context` 按采用角度轮换读取证据引用，只写入完整的已验证证据卡，并记录卡片与字符预算及所有遗漏。预算不足时跳过整张卡，不截断主张。最终综合不得重新读取原始语料、未采用候选或未验证卡来填补叙事。

报告必须同时列出采用角度、拒绝角度及理由。核心问题只有在至少一个采用角度形成有效发现时才算得到回答；如果所有候选都缺证，状态必须是 `core_question_unanswered`。
