# 无预设角度发现

当用户提供资料但不指定分析角度时，Data Lens 不能把请求退回成泛泛的“请明确问题”，也不能一次罗列大量没有证据计划的问题。角度发现是一道受约束的候选生成与筛选过程，不是独立事实来源。

## 先锁定范围

- 只读取用户明确指定的资料类型、目录和时间范围；配套图片、视频或同文异格式不能因为同处一个文件夹就自动进入必需证据。
- 先去重并定义分析单位。未确认同一作者时使用通用质性语料路线；作者或账号元数据一致后，才可升级为同一作者内容路线。
- 小于或等于 20 个可读文本单元时优先全量；更大语料使用主题、时间和形态平衡的分层样本，禁止顺序取前几项。

## 候选角度从哪里来

先建立“单元 × 可观察维度”地图，再从以下信号提出候选：

1. 跨单元稳定重复的结构或证据习惯；
2. 主题、时间、长度、任务或载体之间的明显差异；
3. 与主模式相反的异常样本、冲突或边界案例；
4. 同一对象随时间出现的变化；
5. 用户下一步能据此选择、改进或验证的决策问题；
6. 预期存在但实际缺失的证据通道，但只能写成缺口，不能写成事实。

每个候选必须记录：`angle_id`、问题、为什么值得看、分析单位、所需证据、覆盖计划、可能反例、失败条件和当前状态。

## 角度筛选门

最多形成 8 个候选，最多采用 4 个。逐项检查：

- 与用户目标是否相关；
- 能否仅凭声明范围内的资料回答；
- 是否有覆盖多个单元且包含反例的证据计划；
- 是否与其他候选实质不同；
- 是否能产生可行动或可验证的判断；
- 是否存在把频次当效果、把风格当动机或把共现当因果的越界风险。

没有表现数据时，不采用“什么内容更受欢迎、什么写法效果最好”这类角度；可以分析内容机制并提出后续实验。没有作者范围依据时，不采用人格、动机或完整账号画像角度。

## 采用链

```text
语料地图
→ 候选角度
→ 角度筛选门
→ 分角度证据卡
→ 合同校验
→ 证据校验
→ 角度采用账本
→ 只读取已验证证据卡的有界跨篇综合
```

报告必须同时列出采用角度、拒绝角度及理由。核心问题只有在至少一个采用角度形成有效发现时才算得到回答；如果所有候选都缺证，状态必须是 `core_question_unanswered`。
