# 宿主智能体与 Skill 的协作边界

Data Lens 不替代宿主智能体的理解与判断。两者通过可审计产物协作，而不是把全部语义塞进固定脚本，也不是让宿主绕过合同。

## 宿主智能体负责

- 结合当前原话与可见对话历史理解承接语，保留原始 `decision_question`，另行记录上下文解析和改路线理由；
- 判断共同对象、资料群、分析单位和真正影响用户决策的问题；
- 从已观察现象形成问题地图，判断额外认知引擎是否会带来新的区分证据或决策增量；
- 生成角度、主题、解释、反例、竞争解释和行动候选；
- 识别脚本没有表达的新输入形状，并决定是小型试验还是新增适配器；
- 终稿草稿形成后，用已有 E0 保留表做一次轻量对照，恢复遗漏发现、保持用户要求的行动先后顺序，并清理内部评测语言；
- 面向用户说明证据、风险与下一步。

## Skill 负责

- 全量清点、哈希、去重、版本关系、解析状态和失败账本；
- 有界、分层、可复现的抽样与局部证据定位；
- 路线资格、资料范围门、合同校验、证据校验和采用账本；
- 只从已验证证据卡构建预算受限的综合上下文；
- 阻止把请求成功、候选生成或角度采用误标成核心问题完成。

## 握手规则

1. 多轮承接语没有足够维度时，确定性计划标记 `host_context_review.required=true`；宿主可用可见历史补足意图，但不能覆盖原始问题。
2. 开放混合目录先停在范围门。宿主提出资料群，Skill 校验来源、证据和授权；通过后按选中资料群登记的路线与分析单位继续。
3. 宿主提交的角度和发现都是候选。只有合同、证据、反例、竞争解释和稳健性门通过后才能采用。
4. 认知引擎选择不是角度采用或发现采用。选中的引擎若未产生可区分候选，应正常弃权并返回主路线继续分析。
5. 如果机械步骤在真实任务中重复出现，应收回脚本并加入脱敏真实形状 fixture；只对单次语料成立的解释留在运行产物，不写成全局规则。
6. 终稿轻量对照是同一次写作的最后编辑，不新增账本或门禁。用户要求一个最优先动作、或后续动作依赖前一步结果时，只保留一个第一停止点，其他动作明确后移。

简单单步任务可以由宿主直接完成。只有风险、复现、跨资料覆盖或正式交付需要时，才启用完整账本链。

## 最小充分执行级别

| 级别 | 触发条件 | 默认动作 | 不默认做 |
|---|---|---|---|
| `default_enhancement` | 少量可直接读取资料、普通决策分析 | 宿主先写 E0；核验高影响事实/数字；最多搜索两个 E1；只做直接区分测量 | 不重复生成 scope、angle、finding、increment 多套中间 JSON |
| `evidence_mode` | 大语料、重复导出、跨来源、多模态或明显覆盖风险 | 清点、抽样/全量计划、定位、必要统计和失败账本，再由宿主解释 | 不自动调用 R、OCR、Whisper、向量或 DuckDB |
| `research_grade` | 正式评测、高风险、高级预测/因果采用、正式发布 | 完整合同、采用账本、独立复核、语义一致性与发布检查 | 不把门禁通过当成计算、实验或分析增量 |

升级由资料规模、模态、声明强度和决策风险触发，不由“想显得更深”触发。降级不能删除已经观察到的 E0 发现或跳过关键核证；升级也不能让宿主把同一份材料从头分析第二遍。
