# 跨宿主语义不变量

这份说明用于保持不同宿主对关键分析判断的含义一致。它不要求各模型写出相同措辞，也不以报告结构一致代替分析能力；只约束一旦违反就会改变结论的语义。

## 服务的最终目标

Data Lens 的目标是让“宿主模型 + Skill”在保留宿主原生高价值发现的前提下，更稳定地产生结构不同、预测不同且可直接检验的新解释。加载成功、字段齐全、报告更长和审计更复杂都不算增量。一个宿主若因为使用 Skill 而出现事实、统计、因果或分析单位降级，本轮就没有跨宿主增量。

## 五项不变量

1. **选择后结果不是干预效果。** 推荐、筛选或策略自行决定了谁被观察时，观察到的 CTR、利润或转化率只能描述被选样本。没有随机分流、可辩护的识别设计，或带 propensity、共同支持和敏感性诊断的有效 OPE，不能把与另一批流量的差值写成策略增量。
2. **分析单位不能由相似特征补造。** 没有稳定用户、会话、设备或主体标识时，相同特征元组仍只是匿名记录；不得据此推断同一人的重复曝光、疲劳、学习或迁移。
3. **统计语言必须与复算结果一致。** “显著”“不显著”“方向稳定”和“不确定”必须对应声明的检验、窗口、样本与数值。需要计算时由 Python 复算，不能靠文字印象校准。
4. **实验必须命中机制变量。** 如果核心机制是反馈来源污染，实验就必须操纵、隔离或观察反馈来源；比较模板和原创只检验内容形式，不能直接验证反馈污染。
5. **E0 高价值发现必须逐项承接。** 最终综合读取 `native_baseline.required_findings`，并在内部 `baseline_retention` 中把每项映射到终稿发现。后续证据可以把它标为 `strengthened` 或 `superseded`，但替代项和证据必须明确；不能因 E1 更复杂而让 E0 静默消失。

## 最终报告承接格式

`baseline_retention` 是内部发布检查，不进入读者正文：

```json
[
  {
    "baseline_finding_id": "E0-R001",
    "status": "retained",
    "report_finding_ids": ["F01"],
    "evidence_ids": [],
    "rationale": "月内转折仍是解释行动时点的关键发现。"
  }
]
```

`retained` 与 `strengthened` 至少指向一个终稿发现；`superseded` 同时指向替代发现和支持替代的证据。渲染器只在最终报告发布边界检查是否有静默遗漏，不用这张表评价文字风格或报告篇幅。

终稿草稿形成后，宿主只用这张已有表做一次轻量对照改稿：恢复遗漏的高价值 E0，或保留有证据的替代项；不再创建检查表或重跑分析。用户只要一个最优先动作、或行动之间存在结果依赖时，正文先给一个第一停止点，再把其余动作放到后续阶段。`E0/E1`、`no_increment`、评审状态和其他内部过程词不进入普通读者稿。

## 跨宿主测试

把 [公开语义探针](../evals/semantic-conformance/probes-public.json) 单独复制到隔离目录，只把公开探针交给被测宿主；答案保存后，再由评测侧持有、不会打入宿主安装包的 `expectations-private.json` 复核：

```text
python scripts/data_lens.py assess-semantics \
  --responses codex-responses.json workbuddy-responses.json \
  --expectations <评测侧路径>/expectations-private.json \
  --output semantic-assessment.json
```

因果校准、单位身份、统计校准、机制直接性和基线保留分别报告，不以平均分掩盖任一关键失败。至少两个不同宿主逐项通过后，结果只允许声明 `semantic_probe_stability`；跨宿主真实分析增量仍需完整真实资料盲测中没有严重退化。
