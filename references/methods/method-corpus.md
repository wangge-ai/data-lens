# 方法型资料分析

当用户想理解一批项目、打法、案例、教程或操作规则如何跨资料运作时使用。目标不是概括文档，而是重建可复用动作、适用条件、结果、冲突和失败边界。

## 单位和来源模型

- 来源容器：文件、文档、章节、工作表、截图组或录音录像；
- 主要分析单位：原子方法主张；
- 模式单位：由一个或多个原子主张归一化形成的方法；
- 独立支持单位：来源家族，而不是文件数量。

原子方法主张保存 `actor`、`action`、`target`、`condition`、`stage`、`claimed_outcome`、`evidence_grade`、`source_family`，以及有限摘录或图片位置。一句话含有不同动作、条件或结果时要拆分。推断出来的流程不能伪装成原文引用。

## 必答检查项

| ID | 问题 |
|---|---|
| `unit_definition` | 什么算一条方法主张和一个来源家族？ |
| `method_steps` | 有哪些动作，按什么阶段或顺序发生？ |
| `conditions` | 什么前提、受众、渠道、资源或时机让动作适用？ |
| `outcomes` | 结果是被主张、被观察，还是仅仅被建议？ |
| `evidence_strength` | 哪些有直接记录、作者自述、第三方案例或只有建议？ |
| `conflicts` | 哪些建议不同，差异能否由条件解释？ |
| `failure_boundaries` | 方法会在哪里失败、停止放大或仍未验证？ |
| `next_action` | 最小的复用或验证动作是什么？ |

缺少证据时明确标记，不能直接省略问题。

## 分析步骤

1. 提取前先审核容器内部，排除无关工作表或章节，合并连续截图。
2. 把选中来源拆成原子方法主张，暂时保留原始措辞。
3. 保留直接证据并标记推断字段，计数前先分配来源家族。
4. 归一化角色、动作、对象、阶段和结果，同时保留原始值。
5. 只有成员主张共享相同行动逻辑时才形成候选模式；词语相似不够。
6. 按阶段、条件、主张结果、证据等级和独立来源家族比较模式。
7. 只有来源顺序或重复阶段关系支持时才重建流程，并标记缺失环节。
8. 先把分歧视为寻找隐藏条件的候选，再判断是否真正矛盾。
9. 报告中分开可复用动作、可能机制、主张结果和已验证结果。

## 证据与计数规则

- 重复副本或后续版本不算独立支持；
- 建议、作者自述、实操案例和实测结果是不同证据等级；
- 频次是明确分母内的资料覆盖率，不是真理或有效性；
- 项目声称赚钱，不等于验证利润，除非明确期间、成本和记录；
- 只收录成功案例的资料集合没有合格机会分母和失败样本时，不能估计成功率、普适性或最优打法；
- 同一作者、同一团队或转述链反复出现的主张不能算多个独立支持；
- 不能用信息差、流量红利、信任或某一固定阶段模型解释全部项目；先从可观察动作和条件归纳，再比较候选机制；
- 没有入场、出场和成本规则，次日涨跌不等于策略胜率；
- 流程图可以含推断关系，但每条推断都要标记，不能引用成原文。

## 最低有用交付

1. 大白话流程或阶段图；
2. 条件明确的主要重复方法；
3. 有意义的变体和反例；
4. 证据强度对比；
5. 失败或放大边界；
6. 可复用方法卡或有限验证方案。

除非用户要求，不展示提取台账。面向读者的报告先讲这些方法到底怎么做、何时适用。
