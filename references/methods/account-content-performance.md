# 账号内容与表现分析方法

当文章资料和后台指标同时存在时使用。目标是把已经记录的表现与可能的内容机制分开，并把比较转成下一轮可验证动作。

默认深度为 `deep`。旧合同保留数量下限以兼容历史产物；新合同 2.4 以锚点发现质量为完成门。至少一条重要发现必须完成表现基线、内容对照、反例、竞争解释、稳健性检查和可证伪实验，不能靠凑发现数量通过。

## 必须经过的阶段

1. 用脚本解析后台导出，识别指标定义、时间范围和颗粒度。
2. 清点文章，每篇只保留一个正文主版本。
3. 有稳定 ID 时按 ID 匹配；否则使用发布日期加标准化标题。保留不确定匹配。精确匹配可以进入排名，同日模糊匹配在确认前不得排名。
4. 为每篇文章标记指标状态：
   - `confirmed_total`：存在文章级总量；
   - `partial_channels_only`：只有部分渠道，没有总量；
   - `no_metric_row`：没有匹配指标行；
   - `ambiguous_match`：存在多个可能匹配。
5. 排名和分布只在明确合格集合内计算，并展示分母。
6. 使用 `scripts/select_samples.py --strategy performance_contrast` 选择高、中、低和异常案例。
7. 比较这些案例的正文和视觉特征。
8. 分层报告表现事实、机制线索和待验证实验。
9. 探索性特征比较保留两组样本量、中位数、分母和 `causal_claim_allowed=false`。任一组少于 3 篇时，连稳定的探索性标签都不应下。

## 公众号特殊边界

账号日互动只能描述为同日信号。只有导出明确说明它属于文章级时，才能当作文章指标。当天恰好发布一篇文章时可以说明时间对齐，但导出未提供文章级数据时仍不能计算精确文章互动率。

阅读、点赞、分享、关注和取关记录不能单独解释读者心理、信任、从众、兴趣或对内容观点的认同。文章特征与表现差异先作为待解释现象或支持线索；提出多个内容、分发、时机和测量口径候选解释，并说明下一条数据或配对实验如何区分它们。

## 合格结论示例

- “在 22 篇具有确认总阅读量的文章中，承诺可复用成果的标题中位数较高，这是待验证的内容信号。”
- “最强对照组在首屏是否展示结果上不同，后续可用相近选题做配对测试。”

## 不合格结论

- “标题加上 SOP 会让阅读增长 2.35 倍。”
- “当天记录的 266 次分享全部来自这篇文章。”
- “未匹配文章的阅读量为零。”
- “高分享说明读者信任作者并认同观点。”

## 最低报告内容

- 执行摘要突出 3—5 条会改变内容决策的发现，完整深度分析仍至少包含 6 条发现；
- 证据覆盖和合格分母；
- 已确认文章排名；
- 至少 3 组比较，其中至少两组是文章级配对比较；
- 带原始证据的内容机制线索；
- 下一轮实验和缺失证据。

每个主要实验写明单一改动变量、可比基线、主指标、保护指标、测量周期、最小样本、判定规则、干扰因素和停止条件。历史数据是观察性数据时，实验只能面向未来，不能反向补造历史因果。

每条发现保留反例和边界。执行摘要之后渲染完整分析，不能把本路线压缩成一个前五榜单。
