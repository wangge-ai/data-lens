# 质量检查清单

## 路线

- 主路线直接回答用户的决策问题；
- 每个支持模块有独立用途；
- 新类型先试验，不强套模板；
- 多证据角色的开放目录没有已验证共同对象或共同问题时停在盘点分类；最大资料群不等于目录主线；
- 只有资料群选择门为 `analysis_ready` 时才启动自动找角度和深度分析；
- 没有共同作者或账号证据时，混合资料不得误走同作者路线；
- 路由使用用户原话，未被改写摘要加入的关键词污染；
- 分析维度来自用户问题，无关维度不扩写成填充内容。

## 数据

- 每个指标有单位、分母、期间和合格规则；
- 来源容器数和语义分析单位数分开，计算前确认分析单位；
- 缺失不等于零；
- 精确、模糊、歧义和未匹配状态可区分；
- 确定性结果能从已保存输入复算；
- 抽样产物记录策略、分母、排除和偏差警告；
- 混合运行保存来源图、可恢复状态、单项证据、家族分析和语义关系；已完成阶段不能留下既无证据又无排除说明的来源或家族；
- 模糊的内容与指标匹配在审核前不得排名；
- 普通工作簿逐表审核，无关工作表排除而不是混入；
- 视觉结论引用完成语义审核的素材或画面，不引用图片链接数量；
- 微信作者正文不含评论、作者卡和页面控件；正文边界、抽取物和原文哈希可复核；
- 同作者路线的每篇文章已完成所有声明维度，或明确记为证据缺失/不适用；`reviewed` 附有限观察或证据 ID，且至少两篇存在实质内容观察后才声明内容模式能力；
- 连续经营导出表分别声明采集、业务、推广、退款和快照日期；
- 平台是必选维度，口径不兼容的平台不能强行合并；
- 日表重复主键、字段漂移、文件/行/SKU 数突变、异常值和分子分母错位都必须通过保存的质量门；
- 实体先聚合全部合格行再比较；未出现在导出或榜单中的实体记为 `not_observed`，不能补零；
- 增量复用同时绑定来源哈希、解析器版本、指标版本和完成状态。

## 解释

- 已先区分描述、比较、诊断、解释、预测、干预效果和行动选择；没有用同一模型或同一“深度”标签混淆不同问题；
- 已画出最小数据生成过程：结果、暴露/干预、时间先后、选择过程、已观测与未观测驱动因素；
- 测量、描述、时间、异质性、机制、因果、预测和决策层分别标记 `ready`、`conditional`、`blocked` 或 `not_requested`，没有总分掩盖局部失败；
- 事实、线索和建议在文字与视觉上区分；
- 待解释现象先被证据确认，问题没有预设周期、博弈、信息差、路径依赖或规则目的已经存在；
- 重要机制至少检查一个替代解释，并说明什么新增证据能够区分；
- 触发现象、支持证据、区分证据与反证或冲突证据没有混用；
- 陈述、行为、结果、角色、约束和动机分开；自述或利益一致性没有被写成真实动机证明；
- 时间结论没有从时间点或短窗口跳到趋势、阶段、周期、滞后或因果；阶段有起止信号，不同时间轴没有因日期接近而强行对齐；
- 解释尺度和空间类型明确；个体证据没有直接外推群体、组织、平台、市场或制度；
- 不为得到干净故事而删除反例；
- 采用角度没有被写成已回答核心问题；深度发现同时保留支持、反证、竞争解释、区分证据和稳健性结果；
- 认知增强前的 E0 已冻结并保存首轮全部高价值发现；E1 相对整份 E0 明确改变结构假设并在同一条件下给出不同预测，否则返回 `no_increment`；
- E0 已具备具体问题、机制、竞争解释、预测和决策时只做反证增强，不重跑整套发现流程；
- 模式选择在 E1 生成前完成，候选编译时 E0 与前置简报一致；
- 候选生成与留出复核使用不同轮次，留出证据不与 E0 或生成证据重叠；
- 候选核心机制与实验目标先机械绑定，再由独立复核确认实验直接打在该机制上；实验偏题时，无论结果是否显著都不能声称分析增量；
- 方向、时间、点位、路径和失效条件独立保存结果；没有一个总标签能够覆盖局部失败或不可验证；
- 实验使用预先声明的闭区间时间窗和最低数据粒度；窗口外结果不能修复窗口内失败，粗粒度数据不能评价更细粒度命题；
- 当前 0.2 增量复核的 `holdout_status` 来自与候选冻结规格一致的 Python 实验结果，模型没有手工填写结果方向；`no_increment` 与 `review_incomplete` 保存在内部评测产物中，并按 `e0_only` 排除未通过的 E1，普通读者稿不展示这些流程标签；
- 只有锚点发现能授权核心问题完成状态；报告条目数量没有被当作深度证明；
- 因果措辞与证据强度一致；
- 高级发现由同一决策问题的深度分析计划授权；`prediction`、`causal_effect` 和 `decision_rule` 都有目标、方法、假设、匹配层级的验证类型、支持状态和 `analysis_result` 结果证据；结果文件回显的执行组件与层级专属设计字段和计划逐项一致，原始资料或其他层结果没有冒充当前结果；
- 时间预测使用滚动起点或真正未来留出，训练数据不晚于预测起点，并和朴素基线比较；
- 预测模型竞争使用完全相同的滚动起点、预测期和损失函数；报告配对损失差，未把训练内拟合或不同样本上的分数当成胜出；
- 因果分析先声明干预、反事实、时间零点、随访、估计量和识别策略，再估计并做安慰剂、负对照或替代规格；
- 随机分配、平行趋势、无提前反应、连续性、工具变量条件等识别检查各自引用 `experiment_design` 或 `identification_design` 证据，没有共享一个无关的“已验证资料”状态；
- 设计证据中的分析单位、结果字段、干预、比较、组字段/组值、识别策略与估计目标和当前问题完全一致；
- 高级结果由原始问题与当前证据重新编译，且输入文件哈希、数据证据、实际测量字段和处理/对照映射均与计划一致；
- 未实现适配器的结果合同不能靠自填 `supported` 进入采用链，结论正文不能把实际测量的方向或数值反写；
- 任一必需分析层仍未就绪时，局部估计不得获得 `anchor_eligible` 或把核心问题标记为已回答；
- `ready` 不得冒充 `executed`：计划要求的异质性、机制、因果、预测或决策层必须由已验证且与当前问题绑定的实际结果逐层覆盖；只执行一个因果估计时可以保留该局部结果，但不能声称整个核心问题已回答；
- 结论等级与可发布文字一致：`relationship` 必须使用明确的非因果表述；非 `causal_effect` 不能用明确因果措辞，非 `prediction` 不能断言未来时点或数值，非 `decision_rule` 不能发布规范性行动命令，避免借降级标签绕过实验要求；
- 总体平均值已检查关键分群的方向和幅度，发现相反响应时不再发布单一平均建议；
- 分群至少有两个达到最小样本量的可比子群；描述性分群差异未被写成因果异质性，探索所得分群未在同一数据上冒充确认性结果；
- 机制结果只在同一测量上恰有一个冻结假设命中时计为完成；两者都命中或都不命中时保留 `inconclusive`，不计入分析覆盖；
- 行动建议说明决策者、选项、价值指标、成本、约束、触发阈值和撤回条件；缺一时只给条件式建议；
- 终稿草稿已用现有 E0 保留表做过一次轻量对照；缺失的高价值 E0 已恢复或以证据支持的新结论替代，没有另建账本或重跑分析；
- 用户要求一个最优先动作、或后续动作依赖第一步结果时，正文只有一个第一停止点，依赖动作没有被捆成同一个第一步；
- 策略评估逐动作显示期望净效用、场景范围、约束可行性、相对基线优势与 fallback；约束失败或阈值未越过时不强行选择动作；
- 变化点和覆盖变化只是调查候选，不是原因；
- 重要结论能回到来源、表格行、摘录或图片；
- 实验写明单一变量、基线、指标、判定规则、干扰因素和停止条件。

## 交付

- HTML 能在本地打开且无乱码；
- 读者 HTML 不显示路线 ID、字段名、本地路径、哈希和流水线术语；
- 第一屏展示有用发现，不讲工作流程；
- 普通读者稿不展示 `E0/E1`、`no_increment`、评审状态、路由、合同或账本等内部评测语言；
- `deep_analysis.json` 通过路线和深度合同；
- 合同 2.4 的发现账本哈希有效、报告包含全部采用发现，锚点 ID 与账本一致；
- 所有重要发现、对比、动作、指标边界和限制都出现在 HTML 与 Markdown；机器检查表和完整证据路径可只保留在审计 Markdown；
- `run_manifest.json` 绑定分析、方法、确定性产物、证据位置和交付物哈希；重新计算必须一致，陈旧上下文直接失败；
- `run_gate_validation.json` 的每个输入在渲染前重新核对存在性和哈希；
- “已完成”只指声明样本和声明证据通道，不能写成已覆盖作者全部历史、全部图片或未提供的表现数据；
- 外发前提示私有路径和后台数据；
- `repeated_operational_tables` 工作簿使用筛选表或动态范围，包含平台维度，并和确定性分析结果对账；
- 公式扫描覆盖 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`，图表不写死最后一行；
- HTML 同时检查桌面和手机宽度，宽表可横向滚动，平台筛选或标签不溢出、不隐藏内容。
