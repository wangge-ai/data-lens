# 可证伪的矛盾分析引擎

矛盾分析引擎用于识别同一系统中相互依存、相互制约，并对当前决策结果产生相反作用的机制。它是可选认知引擎，不是默认世界观，也不是固定报告模板。

这里的“矛盾”必须具有共同载体、可观察作用和区分条件。两个指标不同、两个群体有差异或两种意见相反，都不足以构成结构性矛盾。检查后不满足定义时，应返回 `no_structural_contradiction`。

## 操作定义

- **候选矛盾**：两个或多个机制在同一系统边界内相互依赖或争夺约束，并对明确决策目标形成相反作用。
- **结构性关键机制**：在当前范围和发展阶段内，对其他关键现象具有较强规定或解释作用，并得到过程证据和区分证据支持的关系。它回答“什么关系组织了这些现象”。
- **当前行动优先级**：综合预期改善、可控性、成本、风险、可逆性和时限后最值得先做的动作。它回答“现在先动哪里”，可以与结构性关键机制不同。
- **主要矛盾**：本引擎内部用来比较结构性关键机制的候选概念，不直接等同于当前行动优先级，也不是对象的永久属性。
- **矛盾主要方面**：当前净结果主要由哪一方面主导，以及在什么条件下主导关系会转换。不能用绝对数最大自动代替主导机制。
- **普遍性与特殊性**：通用模式只能生成候选；结论必须说明它在哪些对象、时期和条件成立，以及有哪些例外。
- **内因与外因**：相对于显式系统边界区分内部结构与外部条件，并检验二者如何交互。分类随边界改变，不是因素的固定标签。
- **发展阶段**：由可复核起止信号、统计变点、业务事件或驱动排序转换定义的时期。只有时间先后或两个数据点不能证明阶段。
- **实践检验**：把候选解释变成有区别度的预测，通过行动、实验、留出时间窗或对照观察更新判断。

## 候选卡

每个候选至少记录：

- 决策问题、目标指标和系统边界；
- 共同载体、分析单位、对象和时间范围；
- 相互制约的方面及作用路径；
- 宿主普通分析最容易得到的解释 `E0`；
- 结构不同的候选 `E1`，以及它与 `E0` 对同一新证据的不同预测；
- 各方面的预测、贡献或方向；
- 支持、冲突、区分和缺失证据；
- 普遍范围、特殊条件和反例；
- 当前主导方面及可能的转换条件；
- 内部因素、外部因素及交互假设；
- 所处阶段和阶段判定信号；
- 竞争解释、失败条件和实践测试。
- 结构性关键机制与当前行动优先级；若二者不同，分别说明理由；

无法填写共同载体、双向作用路径和至少一个与普通解释不同的区分预测时，不形成候选矛盾。

## 分析步骤

### 1. 固定问题和边界

保留用户原始决策问题，明确要改善的结果、可调整范围和分析尺度。主要矛盾始终相对于这三个条件判断；更换目标、边界或尺度后必须重新比较。

### 2. 围绕问题组织多源调查

从主路线已经核验的材料中组织一张轻量地图：

- 中心问题需要哪些现状、历史、关系和结果证据；
- 每类来源代表什么角色、能观察哪个环节、不能观察什么；
- 不同来源在哪些事实上相互印证、冲突或只是重复；
- 哪些关键角色、时期、对象或机制环节仍然缺失；
- 哪一个缺失最可能改变候选排序。

调查服务中心问题，不以资料数量、多数意见或最醒目的案例代替结构判断。相互冲突的材料先保留为待解释现象；不同角色对同一过程的描述可以互补，但不能自动当成独立因果证据。资料抽样、转换和语义核验继续使用主路线已有方法。

### 3. 从观察生成不同结构的候选

先确认变化、差异或冲突确实存在，再搜索：

- 对结果符号相反但相互关联的贡献；
- 总体与分组的方向反转；
- 资源、容量或规则造成的真实权衡；
- 相同动作在不同对象上的正负效果；
- 时间阶段前后驱动顺序变化；
- 假设竞技场中相互排斥的预测。

同时保留“只是口径、测量、样本结构或随机波动”的空解释。不得把候选名称写进搜索条件后只找支持材料。

把宿主最自然的普通解释记为 `E0`，然后只在材料提供抓手时尝试重构：

- 反转因果方向，检查结果是否也在反过来塑造原因；
- 移动反馈位置，检查问题是否发生在信息产生、传递、采用或回写环节；
- 改变分析层级，检查局部改善是否通过共享资源或规则损害整体；
- 找到具体共同载体，检查同一资产、流程、容量或规则怎样同时传递收益与代价；
- 改变阶段或决策目标，检查原排序在何种条件下翻转。

这些是候选生成动作，不是必须填满的清单。`E1` 若不能对未见资料、对照对象或下一步行动给出与 `E0` 不同的预测，就删除；新奇性本身不能保留候选。

### 4. 在个别、一般和新个别之间往返

先有理由地选择少量代表性、对照性或极端对象，深描其过程和边界；再从多个个别对象归纳带范围声明的暂定关系；最后把关系用于未参与归纳的新对象、留出时期或下一批资料。记录失败、例外和条件变化后修正规则。

便利样本、单个成功案例或同一来源的重复材料不能直接上升为一般结论。若暂定关系在新个别中失败，应缩小范围、拆分候选或放弃，而不是把反例改名为特殊情况。

### 5. 检查普遍性和特殊性

在时间、对象、层级和口径上分层比较：

- 关系覆盖多少分析单位；
- 是否只由少数极端对象驱动；
- 汇总关系在子群中是否反转；
- 共同范围与完整范围是否一致；
- 哪些条件使关系增强、减弱或消失。

通用经验只提供待检验模板。存在稳定例外时，应缩小适用范围或拆成不同候选，不用“特殊情况”消解反证。

### 6. 分开比较关键机制与行动优先级

先比较结构性关键机制：

- 过程证据是否支持作用路径；
- 对关键现象的解释覆盖；
- 与竞争解释相比是否产生不同且已被检验的预测；
- 跨对象、时期或留出案例是否稳定；
- 当前阶段的持续性；

再单独比较行动优先级：

- 对当前决策结果的预计改善；
- 可行范围内的干预空间；
- 成本、时限、可逆性和实施风险；
- 副作用、不可逆性和剩余不确定性。

优先使用现有确定性算子做贡献分解、共同范围比较、敏感性分析或可行区间模拟。核心问题分别是：哪种关系最能解释其他现象；以及若在现实可行范围内采取某个动作，整体缺口预计减少多少、会新增什么风险、还能获得多少区分信息。

这些指标用于透明比较，不组成全局固定公式。容易做、见效快不构成机制证据；解释最深的结构也未必是当前最该先动的地方。两种排序不一致时并列报告，并写出什么可观察条件会改变行动顺序。若候选排序依赖未经验证的权重，或多个候选无法区分，就报告“当前无法确定结构性关键机制”。

### 7. 判断主要方面和转换条件

分别估计各方面对当前结果的方向、贡献和不确定区间，并检查换口径、换样本或排除异常后是否稳定。随后写出可以观测的转换条件，例如费率下降、容量扩充或对象结构改变到何种范围时，净方向可能反转。

如果只能确认双方存在而无法判断谁主导，就保留并列候选。主要方面不得跨时期、对象或系统边界外推。

### 8. 检查内外因交互

先声明系统边界，再比较：

- 外部条件是否作用于所有对象；
- 相同外部变化为何产生不同结果；
- 哪些内部结构放大、缓冲或改变了传导；
- 内部可控动作能否改变外部条件造成的结果。

适用时使用组内/组间分解、交互项、相似对象对照或自然变化。没有交互证据时，只能分别描述内部与外部候选，不能用抽象原则补足机制。

### 9. 识别阶段转换

阶段至少需要一种可复核依据：预先定义的业务事件、统计变点、约束条件改变，或驱动贡献排序持续转换。每个阶段分别说明起止信号、主要矛盾、主要方面和策略含义。

短窗口波动、单次异常或事后挑选日期不能命名为阶段。证据不足时只描述时间变化。

### 10. 回到实践

优先选择既可能改善结果、又能区分竞争解释的低风险行动。实践卡至少包含：

- 要检验的候选与竞争解释；
- 各候选对结果、过程指标和副作用的不同预测；
- 对象、动作、观察窗口和比较基线；
- 成功、失败和停止条件；
- 结果回写证据图和更新假设的方式。

无法干预时，可使用留出时间窗、跨对象复核、自然实验或下一批资料。实践没有按预测发生时，应降低或否定原候选，而不是事后移动解释标准。

## 与证据图协作

矛盾候选对应证据图中的一个有边界子图。事实和计算节点可以通过以下关系连接到候选机制：

- `supports`：与候选预测相容；
- `conflicts_with`：与必要预测冲突；
- `distinguishes`：使竞争候选得到不同判断；
- `constrains`：限制另一机制或行动；
- `moderates`：改变另一因素作用方向或强度；
- `precedes`：只表示时间先后；
- `changes_stage`：满足预先说明的阶段转换信号。

关系名称不能提升证据等级。尤其是 `precedes`、相关和共现都不能直接生成机制边。

## 与假设竞技场协作

每个重要候选至少形成四个可竞争假设：

1. 第一方面当前主导；
2. 第二方面当前主导；
3. 双方交互或第三机制共同造成结果；
4. 现象主要来自测量、口径、选择或随机波动。

竞技场比较各自预测、支持、反证、适用范围和新增证据价值。矛盾引擎负责提出结构和测试，不负责宣布候选采用。胜出候选仍须进入深度发现合同；被击败候选保留失败原因。

## 输出状态

- `structural_contradiction_supported`：结构、主要候选和区分证据均较明确；
- `candidate_only`：存在相互制约迹象，但机制或主导关系尚未区分；
- `principal_unresolved`：候选成立，但当前不能确定主要矛盾或主要方面；
- `insufficient_evidence`：缺少比较、范围或时间证据；
- `no_structural_contradiction`：现有资料不支持结构性矛盾。

这些是推理状态，不是新的完成门，也不替代发现采用状态。

## 读者表达

内部概念默认翻译成普通决策语言：

| 内部概念 | 读者表达 |
|---|---|
| 主要矛盾 | 当前最关键制约 |
| 矛盾主要方面 | 当前主导因素 |
| 特殊性 | 结论成立和例外的条件 |
| 阶段转换 | 何时需要改变判断或策略 |
| 内外因交互 | 外部变化为何在内部产生不同结果 |
| 实践检验 | 下一步怎样用行动验证 |

普通报告不要求引用方法来源或展示哲学术语，只保留事实、机制候选、关键例外、行动和验证信号。

如果结构性关键机制与当前行动优先级不同，读者稿应直接写成“长期真正卡住什么”和“这一步为什么先做另一件事”，并给出优先级切换信号，避免用一个含混的“最关键问题”覆盖两种判断。

## 禁止滥用

- 不把任意差异、正负数或意见冲突强行二分为矛盾；
- 不把最大负贡献自动称为主要矛盾；
- 不用“相互作用”掩盖尚未识别的多因素问题；
- 不用抽象辩证叙事替代统计检验、因果设计或原始证据；
- 不把相关、共现、先后或汇总反转直接解释成作用机制；
- 不预设内因永远重要于外因，也不在未声明边界时分类；
- 不用两个时间点命名趋势、阶段或周期；
- 不静默删除不符合候选的对象、时期和失败实践；
- 不把主要矛盾或主要方面当作跨目标、跨阶段的永久结论；
- 不把最容易实施、最快见效或信息增益最高的动作自动称为结构性关键机制；
- 不把普通解释换一套术语后当作新的深度发现；
- 不套用政治、道德、人格或群体标签解释业务资料；
- 不为追求平衡而虚构证据对称的双方；
- 不在没有可观察预测时声称经过实践检验。
