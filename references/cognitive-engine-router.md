# 可选认知引擎路由

认知引擎是在确定性基线形成之后，用来扩展候选解释、安排区分测试和发现行动线索的可选推理模块。它不是新的资料路线，不替代统计、质性、时间、空间或因果方法，也不改变发现采用规则。

普通任务可以完全不调用认知引擎。认知引擎的输出仍是候选，必须回到证据图、假设竞技场和深度发现流程接受检验。

## 路由位置

```text
用户原始问题
→ 主路线与分析单位
→ 确定性基线和已观察现象
→ 形成决策相关的问题地图
→ 是否存在需要额外结构化推理的信号
  → 否：继续普通发现流程
  → 是：选择能带来不同区分证据的最小引擎集合
→ 候选解释和区分测试
→ 假设竞技场
→ 发现候选与采用流程
```

认知引擎只扩展“可能怎样解释、下一步怎样区分”，不能把描述性证据升级为机制或因果结论。即使认知引擎没有产生有效候选，原主路线也应继续完成能够回答的部分。

## 先形成问题地图

认知路由不能从方法名称开始。宿主先把已观察现象组织成少量候选问题，每个候选说明：

- 它连接了哪些表面现象、对象或来源；
- 如果回答错误，会改变什么决策；
- 当前不确定性来自事实缺失、关系不明、竞争机制还是阶段变化；
- 现有资料能回答到什么强度；
- 哪一项新证据最可能改变判断。

问题优先级综合决策影响、对多个现象的解释覆盖、当前不确定性和可检验性。出现频率、措辞强烈或文件数量不能单独决定“关键问题”。如果多个问题只是同一缺口的不同说法，合并为一个；如果一个大问题包含互不依赖的机制，拆开比较。

路由器的价值不只是选择方法，还要能指出当前最值得追查、但用户尚未直接提出的问题。这个判断仍是候选，必须说明为什么它比其他问题更可能改变决策。

### 不把第一解释当作问题本身

先保留宿主在普通分析中最容易得到的解释 `E0`，再做一次问题重构。重构不是换一种措辞，而是至少改变一个结构假设：因果方向、反馈发生的位置、分析层级、共同载体、决策目标或阶段。形成的 `E1` 只有在能对同一批新证据给出与 `E0` 不同的预测时才保留。

例如，“团队缺少验证能力”是普通解释；“强结论先发布、读者反馈承担低成本边界探测，问题在于反馈没有回写到被复用的观点模块”是另一种结构。后者只有在能够预测哪些反馈会被吸收、多久回写以及下一次复用会怎样变化时才有增量。不能产生不同预测，就返回普通分析，不把同义改写算作认知引擎成果。

认知引擎的最低增量是以下至少一项：发现此前问题地图没有包含的关键问题；提出结构不同且可被区分的机制；找到同时承载收益与代价的具体载体；写出会使当前优先级反转的可观察条件。该要求用于判断引擎有没有贡献，不是新的完成门。

### 多源材料先按问题合成

资料来自不同角色、时期或通道时，先形成轻量的“问题—证据需求—来源角色—一致/冲突—缺失”地图。来源数量不等于独立证据；多数意见也不自动解决冲突。优先比较哪些来源能观察机制的不同环节、哪些只重复同一说法，以及哪个未决事实最能区分候选。资料清点、抽样和语义核验仍复用主路线，不在认知层另建流程。

## 统一引擎接口

每个认知引擎都读取同一组最小输入：用户原始决策问题、系统边界与分析单位、已定位观察、普通解释 `E0`、当前冲突和关键缺失。它返回：

- 重构后的关键问题，或明确说明原问题无需重构；
- 与 `E0` 结构不同的候选及各自作用载体；
- 对同一新证据给出不同结果的区分预测；
- 解释上的关键机制、当前行动优先级及其切换条件；
- 弃权状态、未决证据和失败原因。

不同引擎可以用不同生成方法，但不能改变这些语义职责，也不能自建事实、采用或完成状态。这样宿主智能体可以更换，认知候选仍能进入同一证据图、假设竞技场和发现采用流程。

## 触发信号

只有当前问题与证据同时提供了可检验对象时才调用。常见信号包括：

- 用户要识别当前最关键的制约，而资料中存在多个竞争驱动；
- 总体与分组、短期与长期或两个目标的变化方向冲突；
- 两个以上候选机制对同一现象给出不同预测；
- 同一行动对不同对象产生明显异质效果；
- 时间证据显示驱动因素、约束或有效策略可能发生转换；
- 用户需要把解释转成可观察、可复盘的实践方案。

下列情况默认不调用：

- 简单查数、公式计算、分类、摘要或格式转换；
- 一个确定性分解已经足以回答问题；
- 只有单一时间点、单一对象或无法比较的零散材料；
- 只有抽象概念，没有与之对应的可观察现象；
- 调用只是为了让报告显得复杂或展示方法名称。

## 选择与退出

路由时依次记录：

1. 当前需要解释或决策的现象；
2. 支持调用的具体信号；
3. 所选引擎能新增的候选、测试或决策信息；
4. 它不能回答的部分；
5. 停止条件。

默认只选择一个主认知引擎。只有第二个引擎能产生不同类型的区分证据或显著改变行动时才组合；多个引擎若产生同类问题，只保留更贴近当前证据和决策的一套，不并排输出重复框架。运行状态至少区分：

- `applied`：产生了可检验候选或区分测试；
- `abstained`：检查后没有发现满足定义的结构；
- `insufficient_evidence`：存在信号，但当前资料无法构造区分预测；
- `not_applicable`：问题类型不适用。

`abstained` 和 `not_applicable` 都是正常结果，不得为了维持引擎存在感而补造解释。

如果引擎只增加了边界说明、风险提示或格式完整度，但没有产生新的问题、结构、区分预测或切换条件，也应记为 `abstained`，并由普通分析流程交付这些必要的校准内容。

## 与证据图和假设竞技场协作

认知引擎只能读取已经明确来源、分析单位、时间和范围的事实节点。它可以：

- 提议新的机制、关系、边界条件或实践测试节点；
- 指定哪些现有证据支持、冲突或只能与候选相容；
- 提议需要补充的区分证据；
- 将候选送入假设竞技场比较。

它不能：

- 创建不存在的事实节点或补造缺失值；
- 把相邻、共现或相关关系改写为机制边；
- 绕过竞争解释、反例和稳健性检查；
- 直接把候选写入采用账本；
- 用引擎名称替代方法资格或证据等级。

假设竞技场至少保留一个非目标解释，例如测量、口径、选择偏差或随机波动。候选被证据击败后保留失败原因，但不进入读者结论。

## 面向读者的输出

认知引擎主要服务内部推理。普通报告只展示它带来的决策增量：

- 已确认的关键现象；
- 当前更有解释力的机制候选；
- 会改变判断的例外或替代解释；
- 可执行动作及其验证信号。

默认不展示引擎 ID、路由状态、哲学术语、内部评分或完整候选列表。只有用户明确要求方法说明时，才在附录解释所用框架。

## 当前引擎

- `contradiction_engine`：适用于相互制约的机制、竞争目标、异质效果、主导因素转换和实践检验；详见 [contradiction-engine.md](contradiction-engine.md)。

若未来增加认知引擎，先证明现有引擎和普通候选机制卡无法表达该问题。成为可执行方法后，应按方法治理要求声明版本、适用条件、失败样例和允许结论；不得把路由文档本身当作实现。

## 当前验证结论

首轮两组真实材料前向盲测中，引擎版在内容案例以 95:91 胜出，在市场案例以 88:90 落后，合计只领先 2/200。该结果只支持“校准和替代解释更稳定”，不支持“已经稳定提高深度或决策正确率”。市场案例还暴露出把解释上的关键机制与当前行动优先级混排的问题。

本版据此加入问题重构、具体耦合载体、不同预测和优先级切换条件。修订后在一组全新 12+6 文章样本上，引擎版以 93:85 胜出，三项预注册预测全部得到留出材料支持，裸模型两项支持、一项被推翻。这说明新动作出现了实质增量形态，但仍只有一个修订后独立案例；在更多资料类型和不同宿主上复现前保持实验性。
