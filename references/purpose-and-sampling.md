# 目的识别与抽样

## 先确定目的，再选分析维度

同一批资料可以回答不同问题，必须保留三层：

1. `decision_question`：用户需要决定或改进什么；
2. `primary_route`：主要比较单位和证据逻辑；
3. `requested_dimensions`：真正服务于该决策的维度，如选题、标题、开头、文风、视觉、转化、用户声音、表现或方法提炼。

清点后运行 `scripts/plan_analysis.py`。传入的 `goal` 必须逐字保留用户本轮请求；不要先把它总结成“让 Skill 判断方法和深度”，因为摘要新增的词会反过来污染路由。关键词识别只是可审计的第一版，不是最终裁决。用户关于 Skill、方法或分析过程的元讨论不是资料对象；只有明确要求“从这批资料中提炼方法论”时才走 `method_corpus`。结合用户完整需求和试样复核；用户说得很宽但一条路线仍能解决实际问题时，直接执行并记录次要维度。只有不同答案会改变分析对象或结论含义时才提问。

## 抽样前先分清三件事

1. 来源容器：文件、文档、工作簿、图片组或录音录像；
2. 分析单位：文章、项目、岗位、评论、课程或原子主张；
3. 该来源承载的证据通道。

文件数量不能替代分析单位数量。先用 `inventory_inputs.py` 识别来源容器和候选家族，再用 `select_samples.py` 选择来源组，阅读试样后确认最终分析单位。`analysis_unit_status=provisional_requires_semantic_confirmation` 是真实卡点，不是装饰字段。

| 策略 | 适用场景 | 主要偏差 |
|---|---|---|
| `latest` | 当前内容方向 | 过度代表最近活动和工具周期 |
| `earliest` | 起点或演化基线 | 不能代表当前能力 |
| `spread_time` | 观察时间变化 | 不平衡主题或表现 |
| `balanced_topic` | 作者或资料库整体画像 | 标题主题仍需阅读确认 |
| `performance_contrast` | 对比高低表现线索 | 可匹配、可测量项目可能和被排除项目不同 |
| `pilot` | 未知类型 | 只能形成临时结论，不能代表全量 |
| `stratified` | 混合文档、表格、截图或音视频 | 文件类型平衡不等于语义覆盖 |
| `family_stratified` | 多个资料家族或生产阶段 | 家族标签在语义审核前都是临时的 |
| `full_census` | 规模小且已去重资料 | 成本高，仍需确认分析单位 |

使用 `scripts/select_samples.py` 并保留 `sample_selection.json`。它支持文章、DOCX/PDF、工作簿、表格、图片、连续截图候选和音视频。路线已知时用 `--analysis-unit` 限定来源容器，用 `--include-role` 防止无关证据进入样本。读者报告只用大白话说明抽样规则和偏差，不展示内部路径。

不要把方便样本称为代表性样本。最近十篇只能回答“现在怎样”，不能回答“作者一直怎样”。表现对照要求文章精确匹配且指标属于文章级；模糊匹配在人工确认前继续排除。

可能的版本和连续截图只是审核候选。选择器可以临时选择一个版本或把连续页放在一起，但分析者必须确认关系后才能用于分母。

`mixed_corpus` 先覆盖每个临时家族，再给大体量家族追加样本。首轮后分批扩展，只要新批次仍出现新方法、条件、冲突、版本角色或证据边界就继续。连续两个可比批次不再新增这些信息时，可以记录为本资料库的“编码发现稳定”，不能宣称普遍理论饱和。

## 新类型登记

新路线试验前创建 `novel_case.json`。只有记录临时单位、证据通道、有效输出、失败假设、缺失证据和用户认可后，案例才可复用。升级为正式方法还必须增加方法说明和回归样例，仅仅文字相似不够。
