# 视觉与多模态分析

当结论涉及封面、首屏、页面排版、截图、幻灯片设计、图片节奏、视频节奏或可见转化按钮时使用本规范。

## 覆盖门

运行 `scripts/inspect_visual_assets.py`，微信公众号归档使用默认 `--document-scope auto` 或显式 `wechat-body`，分开记录：

- 像素可读的本地图片，但它们仍需语义审核才能支持结论；
- 能解析到本地文件的引用；
- 尚未实际打开的远程或嵌入资源；
- 缺失或无法读取的资源；
- 仍需转录或抽帧的音视频。

形成视觉结论前使用 `view_image` 检查本地图片。PDF 先渲染页面，视频和课程按代表性片段抽帧并保留转录。清点脚本只能证明覆盖和文件身份，不能替代视觉审核。

混合或陌生资料使用 `scripts/plan_multimodal_fallbacks.py` 创建有限的待处理队列。试验阶段限制页面、图片和时长，只有与决策有关时才扩展。计划记录的是待办，不代表 OCR、转录或视觉检查已经完成。

图片数量、URL、宽高比和 Markdown 位置只描述覆盖，不能证明封面好看、截图有用或页面设计优秀。

微信公众号归档的图片清点和正文映射必须与文本抽取共用正文边界。跨文章重复哈希且位于本地资源末尾，只能识别为“固定尾部资产候选”；实际查看前不能命名为二维码、关注卡或作者头像。已确认排除的页面资源使用 `analysis_eligibility=excluded`，不计入待审图片，也不得映射成正文证据；重新纳入必须记录理由。

## 视觉证据单位

每条非显而易见的视觉结论保留本地来源、`review_status=semantically_reviewed` 和画面描述。需要局部区域时，在已审核图片中记录 `[x, y, width, height]` 像素坐标。

视觉对比要保持视口或素材角色一致：封面对封面、首屏对首屏、同一步骤修改前后对比。

只分析用户需要的维度：

- 封面：层级、承诺、主体、对比度、品牌连续性；
- 首屏：即时回报、信息密度、开头证据、继续下滑动力；
- 正文：标题节奏、段落长度、强调、截图教学作用、留白；
- 教程截图：它教读者做什么判断或动作，而不只是“存在截图”；
- 视频或课程：转录内容、镜头顺序、节奏、演示和练习分别作为证据。

## 边界

- 转换后的 Markdown 可能丢失字体、颜色、间距和裁切信息，这些结论要看原始 HTML 或截图。
- 截图不能证明互动或转化，只能与表现数据一起作为机制线索。
- 没有抓取或查看的远程素材仍是未检查。
- 不能用少量漂亮幻灯片代表整个课程，应按课程或章节抽样。
- 报告图库在需要看完整素材时使用 `fit=contain`；有意裁切时使用 `fit=cover` 并设置经过审核的焦点 `position`。原始证据保持不变并可访问。
