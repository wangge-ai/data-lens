# 证据通道与组合规则

## 各类证据能证明什么

| 通道 | 适合证明 | 单独不能证明 |
|---|---|---|
| `content_text` | 观点、案例、结构、措辞、明确方法 | 阅读、转化、收入 |
| `performance_table` | 明确分母内的计数、比例、日期和排名 | 结果为什么发生 |
| `tabular_data` | 尚未审核的工作簿或表格容器 | 工作表未分配角色前的任何领域结论 |
| `visual_layout` | 封面层级、首屏、字体、间距、可见证明 | 商业效果 |
| `audience_voice` | 已表达的需求、异议、问题和词汇 | 沉默读者或整个市场 |
| `temporal_metadata` | 顺序、新旧、前后关系 | 没有控制条件时的因果效果 |
| `audio_video` | 口述内容、节奏、演示和镜头 | 未检查转录或画面前的可靠结论 |
| `source_metadata` | 作者、来源、资料家族、转载候选 | 独立佐证 |

## 证据在解释中的职责

提出机制或原因时，不只按资料格式分类，还要说明证据在当前解释中承担什么职责：

- `trigger`：确认待解释的现象确实出现；
- `supporting`：与某候选解释相容，但不能单独排除其他解释；
- `discriminating`：能让竞争解释产生不同判断；
- `counter_or_conflict`：与当前解释冲突，或迫使结论缩小适用范围。

同一来源可以在不同问题中承担不同职责，但同一证据不能因为被重复表述就升级。重要解释应保留至少一个替代解释，并说明还缺什么区分证据。参与者自述只证明其公开或记录中的解释；行为符合某种利益只支持动机假设，不确认真实动机。

## 组合规则

1. 保留每条通道的原始来源和稳定 ID。
2. 显式匹配不同通道，状态保存为 `confirmed`、`probable`、`unmatched` 或 `conflict`，不能默认选择最相近标题。
3. 每个指标都携带计量单位和分母。
4. 缺失、排除和不合格必须分开。
5. 表现数据用于选对比案例，正文和视觉证据用于提出机制线索。
6. 说明要把线索升级为更强结论还缺什么证据。
7. 证据覆盖记录为 `available`、`partial`、`uninspected`、`missing` 或 `not_required`。十个图片链接不等于检查了十张图片。
8. 排名前先把表格匹配到内容。模糊匹配只是待审项，不能进入统计。
9. 证据是否存在和处理到哪一步分开记录：`source_only`、`parsed`、`pixel_readable`、`ocr_complete`、`semantically_reviewed`、`matched`，不能统称“已检查”。
10. 复合容器在内部层级审核。一个工作簿可能同时有相关和无关工作表；一个 DOCX 可能包含多个方法单位；截图文件夹可能包含连续页。
11. 每项计算保留指标定义：单位、分子、分母、合格总体、缺失规则、排除、算法版本和解释边界。

## 常见错误

- 把缺失阅读量当零；
- 一天发布多项内容时，把账号日互动全部归给一篇文章；
- 把同一文章的 `.md`、`.html` 和 `.mhtml` 当三篇；
- 仅凭截图判断文章成功；
- 从可见评论外推全部读者偏好；
- 因高表现文章含有某特征，就宣称该特征导致表现；
- 没看原页面或图片，只根据 Markdown 图片数量描述字体、色彩和留白；
- 把像素可读误当语义审核完成；
- 因为属于同一 `.xlsx` 就合并所有工作表；
- 没有入场、出场和成本规则就把次日涨跌称为胜率；
- 连续截图还没合并就把截图数当岗位数。
