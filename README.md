# Data Lens

中文 ｜ [English](README.en.md)

Data Lens 是给 Codex、Claude Code 等智能体使用的本地深度分析 Skill。

它不替代模型思考，也不是另一个数据分析网站。它给智能体补上一套可以真正执行的分析骨架：先认清资料范围和分析单位，再计算、找关系、追解释、查反例，最后把结论、证据边界和第一步行动交付出来。

适合一句话说不清、单看一个文件容易误判的任务：大量经营表、多篇文章与访谈、评论与聊天记录、PDF/图片/音视频，或几种资料混在一起的项目目录。

## Codex、Data Lens，以及两者合在一起

| 组成 | 主要负责 |
|---|---|
| Codex | 理解用户真正关心的问题，读懂语境，形成自然解释，处理没有固定答案的语义判断，并把结果讲清楚 |
| Data Lens | 清点资料，确认分析单位和分母，选择合适路线，执行可复算的提取与测量，连接跨来源证据，检查反例、替代解释和结论边界 |
| Codex + Data Lens | 既保留智能体面对新问题时的灵活判断，又让关键数字、证据位置、推理上限和最终交付可以复核 |

最准确的定位不是“让模型换一种文风”，而是：**让智能体的分析从一次回答，变成一套有证据、有边界、能继续验证的工作结果。**

## 它最独到的六件事

### 1. 可以从“我也不知道该分析什么”开始

面对一个大目录，它不会直接抓最大的文件或最高频词当主题。它先区分资料群、版本、重复项和证据角色，再从现有材料能支持的问题中选择最值得深入的方向。

### 2. 先确认分析单位，再谈数字

文件数不一定是样本数，一张表也可能包含多个观察单位。Data Lens 会分开文件、文章、订单、商品、平台日、图片区域和视频片段，明确分子、分母、缺失与排除项，避免把“有多少文件”误写成“有多少案例”。

### 3. 深度不是报告更长，而是问题逐层推进

它把测量、描述、时间变化、群体差异、机制、预测、因果和行动选择分开。资料只能支持描述时就停在描述；缺少实验或识别条件时，不会把相关关系包装成因果。

### 4. 不只找支持材料，还会主动找会推翻结论的东西

它先保留最自然、最有价值的解释，再寻找这个解释覆盖不了的现象。只有出现结构不同、能给出不同预测的其他解释时，才继续测量；找不到真正的新解释，可以正常停止，不用为了显得深而生造观点。

### 5. 能把不同来源拼成一条证据链

经营表里的变化、评论里的使用反馈、PDF 中的条款、图片中的细节和视频中的时间点可以各自保留位置，再围绕同一个问题综合。检索命中只负责定位，不会被当作全量覆盖或独立事实。

### 6. 同时照顾读者和复核者

读者看到的是结论、依据、其他可能、适用范围和一个最优先动作；计算明细、来源位置、失败记录和运行清单单独保存。主要报告不会被本机路径、哈希和内部流程术语淹没。

## 能分析到什么程度

Data Lens 不给分析打一个模糊的“深度总分”，而是逐层说明已经回答到哪里、下一层为什么能做或不能做。

| 层次 | 回答的问题 | 需要的证据 |
|---|---|---|
| 测量 | 数字和字段到底是什么意思 | 明确口径、单位、来源和缺失规则 |
| 描述 | 发生了什么 | 可复算的事实、数量和分布 |
| 时间 | 什么时候开始变化，是否存在阶段切换 | 可比较的时间点、窗口和同口径序列 |
| 差异 | 哪些商品、群体、渠道或内容不一样 | 合法分组、足够样本和重叠检查 |
| 机制 | 为什么可能发生，还有什么解释 | 至少一个竞争解释、反例和可区分预测 |
| 预测 | 哪种方法对未来更准 | 不泄漏未来的验证和共同预测起点 |
| 因果 | 某个动作是否真的造成变化 | 合格实验或可辩护的识别设计 |
| 决策 | 在收益、成本和约束下先做什么 | 已验证结果、效用规则、风险与撤回条件 |

一次任务不必走完八层。真正的深度，是知道哪一层已经成立、哪一层仍然缺证据。

## 可以分析哪些资料

- 销售、成本、退款、投放、库存等 CSV、XLSX 和重复经营导出；
- 多篇文章、整本书、评论、访谈、案例、研究资料和聊天记录；
- PDF、图片、音频、视频及其组合；
- 多个版本、多个来源、多个子项目混在一起的资料目录。

文件格式只决定怎么读取，用户的问题才决定用什么分析方法。

## 一次完整分析会产出什么

面向读者的交付通常包括：

1. 最值得先看的结论；
2. 支持结论的事实和来源；
3. 重要反例、其他可能和适用范围；
4. 当前最优先的一个行动；
5. 什么结果会支持、缩小或推翻当前判断；
6. 需要时提供离线 HTML、Markdown、可筛选 Excel 或数据附件。

需要复核时，还会保留证据位置、计算产物、未读取或失败项目和运行清单。它们用于追溯，不会默认塞进读者正文。

## 它实际怎样工作

```text
用户的问题 + 指定资料
        ↓
先形成自然分析，不丢掉已有好发现
        ↓
确认资料范围、分析单位、版本、分母和证据能力
        ↓
执行必要的解析、匹配、去重、计算和质量检查
        ↓
寻找最大解释缺口、竞争解释、反例与区分证据
        ↓
只运行会改变判断或行动的进一步分析
        ↓
输出读者报告、复核材料和一个第一步行动
```

资料少、问题简单时，它走轻量路线；资料大、来源多或需要正式预测/因果判断时，才升级到更完整的证据和复核流程。

## 安装

### 运行条件

- 支持本地 Skill 的宿主，例如 Codex、Claude Code 或 WorkBuddy/CodeBuddy；
- Python 3.10 或更高版本，用于确定性清点、计算和验证；
- 使用 `git clone` 安装时需要 Git，也可以从 GitHub 下载 ZIP 后手动放入 Skill 目录。

### 安装到 Codex

Windows PowerShell：

```powershell
git clone https://github.com/wangge-ai/data-lens.git "$env:USERPROFILE\.codex\skills\data-lens"
```

macOS 或 Linux：

```bash
git clone https://github.com/wangge-ai/data-lens.git ~/.codex/skills/data-lens
```

安装后重新打开一个 Codex 任务。已经安装过时，在 Skill 目录运行：

```bash
git pull --ff-only
```

可选验证：

```bash
python scripts/data_lens.py capabilities
python scripts/data_lens.py test
```

### 其他宿主

```text
Claude Code:         ~/.claude/skills/data-lens
WorkBuddy/CodeBuddy: ~/.codebuddy/skills/data-lens
项目内安装:            <项目>/.codebuddy/skills/data-lens
```

WorkBuddy/CodeBuddy 官方格式只要求一份包含 `name`、`description` 和正文的 `SKILL.md`，并允许把脚本、参考资料和资产放在同一 Skill 目录。Data Lens 因此共用同一份分析指令，不为另一个宿主改写能力。

通过 WorkBuddy 图形界面导入时，在仓库根目录运行：

```bash
python scripts/package_workbuddy_skill.py
```

然后导入 `dist/` 中生成的完整 ZIP。分发包只包含运行能力和公开自测材料；不要只复制 `SKILL.md`，否则执行脚本、方法说明和报告模板不会一起安装。结构检查只能证明包能读、脚本能启动，真实分析能力仍要在 WorkBuddy 里用一份新资料实际调用。

官方说明：[WorkBuddy/CodeBuddy Skills](https://cloud.tencent.com/document/product/1831/134516)。

## 怎么使用

安装后，不需要再复制一套长提示词。给出资料位置，以及你真正关心的问题即可。

### 没有预设分析角度

```text
使用 $data-lens 深度分析 D:\资料目录。
我还没有预设角度，请先判断哪些资料属于同一个问题，再找最值得深入的方向。
最后给我关键结论、证据边界和一个第一步行动。
```

### 检查一个现有判断

```text
使用 $data-lens 检查“销量下降主要由价格造成”这个判断。
请找支持证据、相反证据和其他可能；资料不足时明确告诉我还不能证明什么。
```

### 分析大量文章或一本书

```text
使用 $data-lens 分析这些文章。
不要只做主题总结，请跨文章追踪反复出现的机制，主动找会推翻主观点的篇目，
并把最终观点定位到具体原文。
```

### 为业务行动服务

```text
使用 $data-lens 分析经营表、退款记录和客服反馈。
我要决定下个月先调整投放、促销还是商品结构。
请区分描述、解释和因果，只保留一个现在最值得先做的动作。
```

复杂任务可以补充读者、时间范围、必须覆盖的对象和交付格式；方法选择由 Skill 根据问题和现有证据完成。

## 依赖逻辑

默认核心只依赖 Python 标准库。其他能力只在任务确实需要、设备已经具备时启用：

| 任务 | 可能使用的可选能力 |
|---|---|
| XLSX 深度读取与交付 | openpyxl |
| 图片文字与版面 | Pillow、Tesseract 或显式配置的 PaddleOCR |
| PDF 页面渲染 | Poppler |
| 音视频元数据与取帧 | ffprobe、ffmpeg |
| 本地音频转录 | 已存在的本地 Whisper 检查点 |
| 特定统计、时间或空间方法 | R 与对应方法包 |
| 大表或向量召回 | DuckDB、嵌入模型或向量库 |

Data Lens 不自动安装这些组件，不会因为缺少组件而静默换方法，也不会自行把资料发送到外部模型或远程向量服务。缺少能力时，它会降级到现有证据能够支持的结果，或明确告诉你缺什么。实际模型服务的数据处理规则仍由所使用的宿主决定。

## 边界

- 简单公式、单个确定性查数或纯格式转换通常不需要 Data Lens；
- 没有足够证据时，可以给出方法和补证计划，但不能假装已经完成深度分析；
- 相关、聚类、预测准确或模型解释都不能自动证明因果；
- OCR 成功、文件可读和检索命中不等于已经理解资料；
- Data Lens 不是网页应用、后台服务、项目数据库或自动远程模型调度器。
