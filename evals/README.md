# Data Lens evaluations

这个目录回答一个比“测试是否通过”更重要的问题：在相同资料和相同任务下，调用 Data Lens 是否真的比裸智能体产生更多分析增量。

这里不把篇幅、标题数量、术语、流程文件或内部审计当作深度。深度主要看：是否找对核心问题，能否跨材料建立有边界的关系，能否提出比表面归纳更有解释力的机制，是否保留反例与竞争解释，以及建议能否同时改善结果并检验判断。

## 两种评测

1. **可公开复现的行为案例**：使用仓库内脱敏 fixture，检查何时应该发现结构性制约、何时应当弃权。它能验证行为边界，不能单独证明分析质量提高。
2. **真实资料成对盲测**：同一资料、同一基础任务，一份由裸智能体完成，一份只额外调用 `$data-lens`。候选在揭盲前改名为 A/B，由独立评审按同一量表评分。原始资料涉及版权或业务隐私时不随仓库分发，只公开选择规则、提示词、候选输出和可公开的评审结果。

## 成对盲测协议

1. 冻结资料快照、文件选择规则和基础任务。
2. 裸基线不得读取任何 Skill、既有报告或评分量表。
3. Skill 组只比基线多一项：调用当前版本 `$data-lens`。不得读取基线输出、既有报告或评分量表。
4. 两组均面向最终读者写报告；内部哈希、账本、路由、合同和审计过程不进入评分正文。
5. 将输出随机映射为 A/B。评审只读取原始资料、两份候选和 [rubric.json](rubric.json)，不得知道候选身份；可直接使用 [blind-evaluator-prompt.md](blind-evaluator-prompt.md)。
6. 先保存逐项理由和分数，再揭盲。失败案例照常保留，不能只展示胜例。

## 怎样解释分数

- 单案例领先只说明“这次更好”，不能证明普遍更聪明。
- 建议把 `+5` 分且至少两个核心深度维度领先，视为值得继续复现的实质增量信号，而不是发布门或质量担保。
- 要声称稳定增量，至少需要三类相互独立的资料，且不能在某一类持续退化。
- 裸智能体本来就可能给出高质量分析；Data Lens 的目标不是保证每次获胜，而是让问题发现、竞争解释、证据覆盖和验证动作更稳定，并能看见它何时没有带来增量。

## 下一轮最需要的证据

继续增加流程或字段不能替代能力证明。下一轮优先补四类案例：带真实经营结果的混合业务资料、观点互相冲突的多角色访谈、能做留出预测的时间/量化资料，以及图像或视频会改变文字结论的多模态资料。随后再让不同宿主模型执行同一任务，检查增量来自 Skill 还是只来自某一次模型发挥。

当前真实资料测试见 [cases/2026-09-real-world/README.md](cases/2026-09-real-world/README.md)，机器可读汇总见 [results.json](results.json)。两组已完成公开案例中，Data Lens 0.8.1 预发布快照分别以 88.5:83.5 和 89:81 领先裸宿主；逐项结果同时保留了裸宿主的独有优势与双方共同漏项。最终 0.8.1 吸收了盲评暴露的规则缺口，但没有重写候选或分数。历史前向试验使用另一版量表，其分数只用于说明迭代来源，不与本轮混算。
